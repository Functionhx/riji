# 日迹 · 设计文档 v0.2

> 状态：草案 v0.2（2026-10-08）。已定：方向 A、名字「日迹」、Android 用 Kotlin + Compose、
> 存储双副本（腾讯云 + 私有仓库）、公开卡放首页、仓库公开、只支持站长自己的设备（Android 17 / macOS 27）。
> 视觉原型：[`design/prototype.html`](../design/prototype.html)，已选定方向 **A · 纸与墨**。

## 1. 一句话

**日迹是你的个人网站装在口袋里的那一半**：每天自动生成一页，记灵感、做 TODO、
推进长期进度、晚上写一句总结；内容默认只属于你（端到端加密），你点头的那部分
才出现在网站上。笔记能力向下兼容 macOS「备忘录」，外观是全新的「纸与墨」。

### 设计原则

1. **先写下来**。打开就是今天，记一条不超过一次点击；整理、同步、发布都在后台安静发生。
2. **私密是默认值**。服务器、私有仓库只见密文；公开必须逐条、逐次明确触发。
3. **兼容备忘录，不模仿备忘录**。备忘录能做的事日迹都能做（见 §3.2 清单），但长相是日迹自己的。
4. **和网站是一家人**。同一套视觉语言（暖白纸、墨色、宋体标题、等宽小标签、`└` 树形、便利贴黄）。
5. **做完才算完**。每项能力以「保存 → 重启 → 同步到另一台设备 → 导入导出」全部通过为准，
   沿用 Magic Notes《备忘录功能对齐表》的验收口径。

## 2. 从现在的用法出发

站长目前用 macOS 备忘录：每月一个文件夹（`202610`），每天一则（`1007`），一则里有：

| 现在的写法 | 日迹里的样子 |
| --- | --- |
| 手动建 `1007`、放进 `202610` | 每天零点（按发布时区，默认 UTC+8）自动生成今天页，自动归月 |
| `Spark` 下的编号清单 | **Spark** 区：一排便利贴；可升级成任务、送进网站 Spark、标记为网站开发项 |
| `TODO` 圆圈勾选 | **TODO** 区；没做完的第二天自动延续，标「↻ 已延续 N 天」 |
| `电路 18 讲` | 识别成**长期进度**（18/40），每天推进，侧栏常驻进度条 |
| 截图、随手一句 | **随记** 区：富文本、图片、附件，和备忘录一样 |
| 清单第 8 条「每日日志提醒功能」 | **晚间总结**：到点提醒，一张卡片总结今天，可一键发成网站日志 |

## 3. 功能

### 3.1 每日层（MVP）

**今天页**

- 自动生成；标题是日期（`10 月 8 日`），副标题星期与「今天还剩 13 小时 38 分」。
- 顶部一条**墨线**：06:00–24:00 的进度，赭色圆点是「现在」。
- 默认三区：TODO / Spark / 随记。区块可折叠、可调顺序、可增删；区块也只是普通的块（§6），
  所以今天页同时是一则完整的笔记。

**TODO 与延续**

- 圆形勾选框，回车续写、Tab 缩进（与备忘录一致）。
- 跨天：未完成项在新一天出现在今天页顶部（「从昨天带来」分组），计数 `↻ N 天`；
  原来那天保留「已延续到 10/08」的灰色记录，历史不被改写。
- 第 3 天起轻提示一次：拆小 / 放进「以后」/ 保持。不弹窗、不打扰。

**长期进度**

- 写 `电路 18 讲`、`马原 第 6 章`、`英语单词 26 天` 时识别为进度候选，点一下确认单位与目标
  （如 40 讲）。之后在 TODO 里勾选即推进，也可手动调整。
- 侧栏（macOS）/「进度」标签（Android）显示全部进行中的进度条与最近推进日。

**Spark**

- 一条一张便利贴（黄 / 粉 / 薄荷 / 雾蓝，手写体），和网站文章便利贴同一种纸。
- 操作：升级为 TODO；送到网站 Spark（加密，网站 /spark/ 可见）；标为「网站开发项」。

**晚间总结与提醒**

- 默认 22:30 本地通知（时间可调，可关）。
- 总结卡：完成 N、延续 N、新增 Spark N、推进了哪些进度，加一句你自己写的话；
  热力图记一格（颜色深浅 = 当天完成量）。
- 卡片上两个开关：公开今日进度（§3.3-②）、发成网站日志（§3.3-③）。

**时间线与月份**

- 时间线：按天倒序的卡片流，可按月份跳转；保留站长「每月一个文件夹」的心智。
- 全局搜索：标题、正文、附件文件名；之后加图片 OCR。

**热力图与连续天数**：一年的格子，今天描赭色边；连续记录天数显示在今天页眉。

### 3.3 和网站的连接（站长选定的三层）

① **加密多设备同步**：手机、Mac 与网站 /spark/ 看到同一份内容；服务端与私有仓库只见密文（§8）。

② **选择性公开进度**：网站首页一张「今天在做」卡片与一年热力图，**只公开数字**：
`今日 2/5 · 连续 12 天 · 电路 18/40`。哪些进度可公开由你逐项勾选；内容永远不公开。

③ **一键发成网站日志**：晚间总结卡 →「发成日志」→ 在 App 里预览成网站文章的样子 → 确认后
由保险库服务提交为 `_posts/<date>-<slug>-zh.md`（`kind: log`），出现在网站「日志」栏目。
发出的是一份新的公开稿，私密原文不变。

不做：读取网站访客数据、在网站上编辑日迹（网站只做展示与 /spark/ 查看）。

### 3.4 AI 总结（可选、默认关闭）

- 设置里明确开启后，晚间总结卡多一个「帮我写一段」：把**当天**内容发给模型，生成草稿，
  你修改后再保存。开启页写清楚「这一步会把当天内容发送给 <模型提供方>，端到端加密在这一步不成立」。
- 模型调用走站长自己的服务（与宠物大脑同样的 Worker 模式：密钥在服务端、每日额度、不记录内容）。
- 关闭时日迹不与任何模型通信。

### 3.5 非目标（v1）

多人协作；公开分享链接；Web 版编辑器；Windows / iOS / iPad（架构预留，v1 不交付）。

**字体**：标题宋体（思源宋体 / Songti SC，Android 打包思源宋体子集）；正文系统无衬线（苹方 / Noto Sans CJK）；
标签与数字等宽（SF Mono / JetBrains Mono）；Spark 手写体（霞鹜文楷子集，与网站同源，SIL OFL）。

### 4.2 标志性组件

- **墨线**：今天的时间进度，2px，赭色圆点为「现在」，下方等宽刻度 `06:00 · 现在 10:22 · 24:00`。
- **区块标题**：等宽、字距 0.14em、全大写（`TODO 2 / 5`），下有一条细线。
- **圆形勾选**：未完成为 1.5px 描边；完成为墨色实心加白勾，文字变 `ink-3` 加删除线。
- **延续徽标**：`↻ 2 天`，赭色等宽，细描边圆角。
- **进度条**：等宽字符 `▓▓▓▓░░░░░ 18/40`（与网站文章侧栏一致），侧栏另有 3px 细条。
- **Spark 便利贴**：手写体、轻微随机倾斜（±1.5°）、顶部半透明胶带。
- **速记条**：底部墨色胶囊（`记一条… 🎙 📷 ＋`），「＋」是一小块便利贴黄。
- **网站卡**：虚线边框，写明「网站上公开：今日 2/5 · 连续 12 天」，只列将公开的数字。

### 4.3 动效与可达性

- 只有三种动效：勾选（圆点填墨 120ms）、便利贴贴上（轻按一下，同网站）、墨线随时间推进。
  遵守「减少动态效果」。
- 触控目标 ≥ 44pt / 48dp；动态字体 / 字号缩放；VoiceOver / TalkBack 标签齐全；
  深色模式是一等公民，不是反色。

### 4.4 平台适配

- **Android**：Material 3 的结构（底部导航、预测式返回、边到边），用 §4.1 的令牌重新着色，
  不用 Material 默认紫色；动态取色关闭（品牌色固定）。
- **macOS**：原生窗口与工具栏、三栏（侧栏 220 / 正文 / 右栏 270，可收起），
  快捷键沿用备忘录（`⇧⌘T/H/J/B/M`、`⇧⌘7/8/9`、`⇧⌘L`、`⌥⌘T`、`⇧⌘A`、`⌘K`）。

## 6. 数据模型：跨平台块格式 v1

> 背景：Magic Notes 用 RTFD 保存富文本，这是 Apple 专有格式，Android 读不了。
> 日迹以**块**为同步与存储的正本；各平台的编辑器只是块的视图。RTFD / HTML / Markdown 只在导入导出时出现。

### 6.1 实体

```text
Note        { id, kind: note | day, title, folder_id?, tags[], pinned_at?, locked, created_at, updated_at, deleted_at? }
Day         { note_id, date: "2026-10-08", tz: "Asia/Shanghai", summary?, mood?, public_stats?, log_url? }
Block       { id, note_id, parent_id?, order, type, attrs, text?, created_at, updated_at, deleted_at? }
Progress    { id, name, unit, current, target?, public: bool, archived_at? }
ProgressLog { id, progress_id, day, delta, block_id? }
Folder      { id, name, parent_id?, order }
Attachment  { id, block_id, mime, bytes, sha256, width?, height?, name }
```

- `id`：UUIDv7（时间有序，便于同步游标与调试）。
- `order`：分数索引字符串（如 `a0`、`a0V`），插入不改动兄弟块。
- `Day` 与 `Note` 一对一：今天页就是一则 `kind: day` 的笔记。

### 6.2 块类型

| `type` | `attrs` | 对应备忘录 |
| --- | --- | --- |
| `paragraph` | `style: body | title | heading | subheading | mono | quote` | 段落样式 |
| `list` | `style: bullet | dash | number`, `indent` | 列表 |
| `check` | `checked`, `indent`, `carry_from?`, `carried_days`, `progress_id?` | 清单 / TODO |
| `spark` | `color`, `promoted_to?`, `site_spark_id?`, `site_dev?` | Spark |
| `table` | `rows`, `cols`, `cells: [[RichText]]` | 表格 |
| `image` / `file` / `audio` / `scan` / `sketch` | `attachment_id`, `caption?` | 附件 |
| `divider` | — | 分割线 |
| `section` | `collapsed`, `title` | 今天页的区块、可折叠标题 |

**RichText**：`[{ text, marks?: { b, i, u, s, code, hl: color, color, link: url | note:id } }]`。
不允许任意 HTML。

### 6.3 跨天延续

延续不复制历史：在新一天插入一个 `check` 块，`carry_from` 指向原块，原块 `attrs.carried_to`
记下新块 id；原块在原来那天显示为灰色「已延续」。勾选新块时，原块状态不变（历史真实）。

## 7. 本地存储

- 两端同一个 SQLite 模式（Android：Room；Apple：GRDB），表即 §6.1 的实体，另有 `sync_state`、`outbox`。
- 附件以内容寻址文件保存（`attachments/<sha256>`），数据库只存元数据。
- 全文检索：SQLite FTS5（中文按字切分 + 常用词）。
- 本地数据库落在系统保护目录（Android 应用私有存储；macOS App Sandbox 容器），
  文件级加密依赖系统（Android FBE、macOS FileVault）；端到端加密只作用于离开设备的数据（§8）。

## 8. 同步与加密协议 v1

### 8.1 密钥

```text
网站保险库根密钥 R（已有：浏览器生成，口令 + 通行密钥包裹，服务器不可解）
  └─ 日迹密钥 K_riji = HKDF-SHA256(R, salt = keyring.riji_salt, info = "functionhx:riji:v1:epoch=<n>")
       └─ 每条记录的数据密钥 DEK（随机 32 字节，AES-256-GCM），用 K_riji 包裹
```

- 设备只持有 `K_riji`，**拿不到 R**：日迹设备丢失不会危及网站 Spark。
- 网站 /spark/ 解锁后持有 R，可派生 `K_riji`，因此网站能查看日迹（只读）。
- `epoch` 用于密钥轮换（撤销设备时递增，§8.3）。

### 8.2 设备配对（不依赖跨平台通行密钥）

> 为什么不直接用通行密钥：现有通行密钥绑定 `vault.fanyuchen.com.cn`，PRF 输出属于具体那一把凭证；
> iCloud 钥匙串与 Google 密码管理器里的凭证不是同一把，算不出同一个值。

1. 新设备在硬件里生成配对密钥对（Apple Secure Enclave P-256；Android Keystore P-256，
   需要生物识别 / 锁屏凭证才能使用），通过已登录的原生会话提交「配对请求」（公钥 + 设备名），
   屏幕显示 **6 位配对码**。
2. 在已解锁的一端（网站 /spark/ 解锁页，或一台已配对的设备）输入配对码，取回该请求。
3. 两端各自用双方公钥计算 **安全比对码**（SAS，4 个中文词），站长确认两边一致 ——
   防止服务器替换公钥做中间人。
4. 已解锁端用 ECDH(P-256) + HKDF + AES-256-GCM 把 `K_riji` 封装给新设备公钥，上传「设备信封」。
5. 新设备取回信封、用硬件私钥解开，`K_riji` 存入 Keychain / Keystore（生物识别保护）。

离线兜底：导入保险库恢复包（`magic-spark-vault-recovery.json`）在本机派生 `K_riji`。

> 荣耀国行机型没有谷歌服务（GMS）：不能依赖 Google 密码管理器的通行密钥与 FCM 推送。
> 配对只用 Android Keystore；提醒用本地精确闹钟；同步在应用前台与 WorkManager 周期任务中进行，
> 需要在系统设置里允许日迹自启动与后台运行（首次启动时引导）。

### 8.3 双副本的分布式同步

站长的要求：腾讯云与 GitHub 私有仓库**都**保存数据，任何一处坏掉都不丢、都能继续同步。
核心做法是**每台设备一条只追加的加密日志**：

```text
设备 A 的日志：A#1 → A#2 → A#3 …        每段 = 一批变更（加密），带序号与前一段的哈希
设备 B 的日志：B#1 → B#2 …
副本 = 所有设备日志段的集合            腾讯云 SQLite、GitHub 私有仓库、每台设备本地，都是副本
状态 = 把所有段里的变更按 HLC 合并      同一条记录取 HLC 最大的那次写入
```

为什么这样设计：

- **存储层没有写冲突**。每台设备只写自己的日志，副本之间同步就是「取并集」：谁缺哪一段就补哪一段。
  腾讯云和 GitHub 不需要谁是主、谁是从，也不需要分布式锁。
- **任一副本都能单独提供同步**。腾讯云挂了，设备直接读写 GitHub；GitHub 不可达（国内网络常见），
  只走腾讯云；之后两边互相补齐（反熵）。
- **服务器作恶也只能「藏」不能「改」**。段用 `K_riji` 认证加密，并按序号与哈希链串起来：
  副本漏给某一段，客户端能从序号断档与哈希链发现；伪造或篡改会在解密时失败。

**段的格式**

```json
{
  "v": 1, "device": "<设备 id>", "seq": 42,
  "prev": "<上一段密文的 SHA-256>",
  "epoch": 1, "hlc_max": "<本段最大 HLC>",
  "ct": "<AES-256-GCM 密文；AAD = v|device|seq|prev|epoch>"
}
```

明文是一批变更：`[{ id, type, hlc, deleted?, value? }]`（`value` 为 §6 的实体）。
服务端看得到设备 id、序号、大小和时间，看不到任何内容，也看不到哪条记录被改了。

**同步一轮**

1. 客户端持有**版本向量** `{A: 41, B: 17, …}`（每台设备已收到的最大序号）。
2. 拉取：`GET …/riji/segments?have=<版本向量>` → 副本返回缺的段。
3. 推送：把本机新写的段（`A#42…`）`PUT` 到副本；副本只接受「接在已知序号后面且 prev 吻合」的段。
4. 同一轮里客户端可以**同时**对腾讯云与 GitHub 做 1–3；任一成功即算同步完成，另一个下次补。

**两个副本**

| 副本 | 存法 | 访问 |
| --- | --- | --- |
| 腾讯云（主力，国内快） | `spark-vault` 服务旁的 SQLite：`segments(device, seq, prev, size, ct, received_at)` | 原生会话（已有的 Magic Bridge PKCE 登录） |
| GitHub 私有仓库 `functionhx-spark-private` | `riji/log/<device>/<seq 补零到 8 位>.json`，一段一个文件 | 单独的 GitHub App「Riji Sync」，**只装在私有仓库**、只有 Contents 读写；设备用 GitHub 设备流程登录，各自持有可过期的令牌（存 Keychain / Keystore），App 里不放任何密钥 |

- 腾讯云每 5 分钟把新段批量提交到私有仓库（一次提交多段），并定期从仓库拉回设备直写的段，两边收敛。
- 私有仓库的提交数随同步批次增长，每天大约十几到几十个；Git 历史本身就是一份可审计的变更记录。

**快照与压缩**

- 日志会一直变长。任一设备可以生成**快照**：某个版本向量下的完整状态（加密），
  存为 `riji/snapshots/<版本向量哈希>.json`。新设备先下最新快照，再拉之后的段。
- 被快照覆盖、且所有活跃设备都已确认收到的段，可在 90 天后从腾讯云清理；
  私有仓库保留完整历史（可选按年归档）。

**冲突、删除与撤销**

- 同一条记录的并发修改：按 HLC **块为单位 last-writer-wins**；块很小（一个清单项、一张便利贴、一段话），
  丢失面很小。被覆盖的版本留在本地「冲突历史」7 天，可一键恢复。
- 删除是墓碑（`deleted: true`），快照时清理超过 30 天的墓碑。
- 撤销设备：删除其设备信封并 `epoch + 1`，之后的段用新 `K_riji`；撤销设备的日志不再被接受。
  如实说明：**已被撤销设备读到过的内容无法收回**。

**附件**：单独加密的内容寻址对象（`riji/blobs/<密文 SHA-256>`），同样存两份；段里只引用哈希。

**跨平台测试向量**（`spec/test-vectors/`）：同一组段在 Kotlin 与 Swift 两端解密、合并后必须得到
逐字节相同的状态；含乱序到达、重复段、序号断档、哈希链被篡改、epoch 轮换等用例。

### 8.4 手动同步（站长要求，P3 第一个上线）

自动同步之外，任何时候都能**手动拉取 / 推送**，并且看得见每个副本的状态：

- **入口**：Android 时间线与今天页下拉刷新、「我 → 同步」里的「立即同步」；macOS 菜单「文件 → 立即同步」（`⌘R`）
  与侧栏底部的同步状态。
- **状态面板**：每个副本一行——`腾讯云 ✓ 10:22 · 本机领先 0 段` / `GitHub ✓ 10:20 · 缺 2 段`，
  以及本机待推送的段数。点某一行可以**只对这个副本**拉取或推送（例如国内网络下 GitHub 不通时，只用腾讯云）。
- **结果**：完成后显示「拉回 3 段、推送 1 段、合并 5 条记录」；有被覆盖的版本时给出「冲突历史」入口。
- **离线**：没网时按钮仍可点，明确提示「已排队，联网后推送」，不假装成功。

自动同步（前台进入、编辑停顿 5 秒、WorkManager 周期任务）在手动同步稳定后再打开，两者走同一条代码路径。
